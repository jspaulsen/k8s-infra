# Vikunja PR Sync

A CronJob (every 5 minutes, namespace `vikunja`) that moves Vikunja tasks across
the kanban board to match the GitHub PRs that reference them. Manifests and the
script are in `applications/vikunja-sync/`.

## How it works

A PR references a task by writing `vikunja#<id>` in its title or body; `Vikunja #<id>`
and `Vikunja: [#<id>](<link>)` also count, but a bare task link such as
`[#25](http://vikunja.lan/tasks/25)` does not (those are usually follow-ups). Each run
reads every open PR, plus PRs closed in the last `LOOKBACK_DAYS` (default 7), from
each repo in `REPOS`. For each referenced task:

| Its PRs                         | Task moves to |
|---------------------------------|---------------|
| Any PR open                     | In review     |
| All closed, at least one merged | Done          |
| All closed, none merged         | Backlog       |

It also comments each PR's link on its task once. It keeps no state; reruns are
no-ops. The task's project needs kanban buckets named exactly `Backlog`,
`In review` and `Done`, otherwise the task is skipped with a warning (the Hearth
project has them; Inbox does not).

The job uses a stock `ghcr.io/astral-sh/uv` image; `uv` installs the script's one
dependency (`requests`) from its inline `# /// script` block at start-up, so the
pod needs outbound access to PyPI and api.github.com. `sync.py` is mounted from
the `vikunja-sync-script` ConfigMap, generated by kustomize from the file.

## Initial Deployment

1. Create the Secret by hand (kept out of git; the repo is public):

```bash
read -rsp 'GitHub token: ' GH; echo; read -rsp 'Vikunja token: ' VK; echo
kubectl -n vikunja create secret generic vikunja-sync \
  --from-literal=GITHUB_TOKEN="$GH" --from-literal=VIKUNJA_TOKEN="$VK"; unset GH VK
```

- `GITHUB_TOKEN`: fine-grained PAT, read-only *Pull requests* on the repos in `REPOS`.
- `VIKUNJA_TOKEN`: Vikunja → Settings → API Tokens: read projects and views,
  read and move tasks, read and add comments.

2. Push `applications/vikunja-sync/`; the `applications` ApplicationSet picks it
   up as the `vikunja-sync` app. (It also creates an empty `vikunja-sync`
   namespace via `CreateNamespace=true`; the resources live in `vikunja`.)

## Operations

Trigger a run outside the schedule (the script also accepts `--dry-run`, which
logs changes without making them):

```bash
kubectl -n vikunja create job --from=cronjob/vikunja-sync vikunja-sync-manual
kubectl -n vikunja logs -f job/vikunja-sync-manual
kubectl -n vikunja delete job vikunja-sync-manual
```

A healthy run logs `INFO N PRs read from 1 repos; M reference a task` and exits 0.
A 401 from Vikunja or GitHub means a token is wrong or expired; recreate the
Secret.

- **Add a repo:** append it to `REPOS` (comma-separated) in `cronjob.yaml` and
  make sure the GitHub token covers it. Vikunja task IDs are global, so one job
  covers all repos.
- **Upgrade uv:** bump the pinned image tag in `cronjob.yaml`.
